# QR-in-Chat Phishing Detection Lab

Companion code for [The Watch Sale, the QR Code, and the Filter That Never
Looked](https://ghostintheprompt.com/articles/the-watch-sale-the-qr-code-and-the-filter-that-never-looked)
on [GhostInThePrompt.com](https://ghostintheprompt.com). The article covers
the incident and the argument; this repo is the actual code referenced in
it — `detector.py` (50 lines of real logic, 84 total with the docstring and
spacing) is run for real, not pasted as an illustration.

## The real incident

Selling a watch on eBay. A "buyer" messages through eBay's own chat and sends
an image — not text, not a link, a QR code — asking me to scan it. No context
for why a buyer would need me to scan anything to buy a watch.

The part worth noticing isn't the scam itself (QR-code redirect scams aren't
new). It's that the image reached me at all. A text-pattern message filter
scanning for suspicious keywords or raw URLs in the message body never sees a
payload that isn't text — it's pixels. Whatever inspection eBay runs on
message bodies, it didn't catch this, because there was nothing text-shaped
to catch.

## What this lab demonstrates

Two pieces, both run for real (`detector.py`, no mocked output):

1. **`generate_sample_qr()`** — builds a QR image carrying an off-platform
   redirect URL, standing in for the attacker's image attachment.
2. **`scan_image()`** — decodes the QR (OpenCV's built-in detector, no manual
   zbar setup) and runs the extracted URL through basic reputation
   heuristics: off-platform domain, known shortener, high-abuse TLD, missing
   HTTPS.

This is the step a text-only message filter skips. It's not novel computer
vision — `cv2.QRCodeDetector` is stock OpenCV — which is the actual
indictment: the fix is cheap and available, not a research problem.

## Run it

```
python3 -m venv .venv && source .venv/bin/activate
pip install "qrcode[pil]" opencv-python-headless
python3 detector.py
```

Output:

```
Decoded payload from image: https://bit.ly/ebay-release-payment-x92
Risk level: high
  - off-platform domain: conversation claims to be a marketplace transaction, link does not resolve to the marketplace's own domain
  - known URL shortener: destination is hidden behind a redirect, can't be inspected before clicking
```

## Scope and honesty notes

- This models the *class* of gap (image payloads evading text filters), not
  eBay's actual internal moderation code — nobody outside eBay can see that,
  and this lab doesn't claim to.
- The heuristics here are intentionally basic (domain/shortener/TLD/scheme).
  A real pipeline would add domain-age and reputation-feed lookups; those
  need paid threat-intel API access this lab doesn't have, so they're named
  as the next step, not faked.
- No real eBay systems, accounts, or data were touched. The QR image and URL
  are both synthetic, generated by this script.
